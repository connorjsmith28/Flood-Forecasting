Pipeline Stages

Stage 1
USGS Site Discovery
Dagster · extraction_job
src/elt/extraction/usgs.py

Queries USGS NWIS for all streamflow/discharge sites within the Missouri River Basin (HUC 10). Three API calls determine data availability:

nwis.what_sites(huc="10", parameterCd="00060")   # all sites
nwis.get_info(sites=[...])                         # per-site detail
→ has_iv   = site has instantaneous (15-min) values
→ has_daily = site has daily mean values

All sites are stored with no further filtering at this stage.

raw.site_metadata ~HUC-10 sites site_id · lat/lon · drainage_area_sq_mi · state_code · has_iv · has_daily
Stage 2
Streamflow & Weather Extraction
Dagster · extraction_job
src/elt/extraction/usgs.py
src/elt/extraction/nldas3.py

Streamflow (USGS): Batches of 20 sites, 365-day windows, 5 parallel workers. Incremental — only fetches after the last stored timestamp.

IV  → raw.streamflow_15min   (site_id, datetime, streamflow_cfs, gage_height_ft, qualifiers)
DV  → raw.streamflow_daily    (site_id, date,     streamflow_cfs_mean, gage_height_ft_mean)

Weather (NLDAS-2): Maps each site to its nearest 0.125° grid cell, downloads hourly NetCDF from NASA GES DISC, area-weighted average per site.

raw.nldas3_forcing  →  air_temp_c, specific_humidity_kgkg, surface_pressure_pa,
                        wind_u/v_ms, shortwave_radiation_wm2, longwave_radiation_wm2,
                        precipitation_mm, convective_precip_fraction, cape_jkg,
                        potential_evaporation_mm
raw.streamflow_15min raw.streamflow_daily raw.nldas3_forcing

Stage 4
dbt Marts Layer
Dagster · transformation_job
src/elt/transformation/models/marts/

Business-logic models. Key tables:

fct_streamflow_hourly
  = stg_streamflow  (aggregated 15-min → hourly)
    INNER JOIN dim_sites
    INNER JOIN stg_nldas3_weather
  → site_id, observation_hour, lat/lon
     streamflow_cfs_{mean/max/min}, gage_height_ft_{mean/max/min}
     + 10 weather variables

dim_catchment_attributes
  = JOIN: 25× stg_gagesii_* + stg_hydroatlas + stg_nldas_climate
  → ~200+ static basin attributes per site
    (geology, soils, land cover, hydrology, climate, dams…)

fct_streamflow_daily    ← daily data + daily-aggregated weather

lp3_filtered_sites
  = seeds.lp3_results
    WHERE flood_severity_score >= 1.25

gauge_streamflow_availability
  = stg_info + stg_gagesii_basin
    WHERE huc02 IN ('10U', '10L')  -- Missouri Basin only
marts.fct_streamflow_hourly marts.dim_catchment_attributes marts.fct_streamflow_daily
Stage 5
dbt Final Layer
Dagster · transformation_job
src/elt/transformation/models/final/

Denormalised ML-ready tables. Three primary outputs:

final.flood_model         (primary training table, hourly)
  = fct_streamflow_hourly
    INNER JOIN dim_catchment_attributes ON site_id
  → ~350+ columns: all weather + all static basin attributes
    batched_table: 25 sites at a time to manage memory

  = fct_streamflow_daily + dim_catchment_attributes

  = SELECT site_id, date, MAX(streamflow_cfs_max), MAX(gage_height_ft_max)

Stage 7
LP3 Flood-Frequency Analysis
Log_Pearson3_Flooding.ipynb
notebooks/data_exploration/

Offline notebook consuming flood-dataset-daily-summary:latest. Uses Bulletin 17C methodology to fit per-site flood-frequency distributions.

1. Load flood-dataset-daily-summary:latest from W&B
2. Extract annual peak flows (water year Oct–Sep) per site
3. Keep sites with ≥ 10 years of record
4. For each qualifying site:
   a. log₁₀-transform peaks → compute mean_log, std_log
   b. Station skew G  (Griffis & Stedinger 2009 unbiased estimator)
   c. Regional skew (state-specific:  NE/SD/ND → −0.30,
                                      KS/IA   → −0.20,
                                      CO/WY/MT → −0.10, …)
   d. Weighted skew Gw = MSE-weighted blend of station + regional
   e. Multiple Grubbs-Beck test → identify & remove PILFs
   f. Fit Pearson Type III via scipy.stats.pearson3.ppf
   g. Compute return-period quantiles Q2/Q5/Q10/Q25/Q50/Q100
   h. Count historical peaks exceeding each threshold
5. Save lp3_results.csv → commit as dbt seed
lp3_results.csv (dbt seed) Q2 · Q5 · Q10 · Q25 · Q50 · Q100 flood_severity_score per site

flood_severity_score — Formula Detail

Each site's flood record is scored by weighting historical floods by return period severity, then normalising by record length. Higher return-period floods receive a larger weight via √T.

# Isolate floods in each tier (between return periods)
count_Q100 = floods > Q100
count_Q50 = floods > Q50 − count_Q100
count_Q25 = floods > Q25 − count_Q50 − count_Q100
...
count_Q2 = floods > Q2 − (all higher tiers)

# Weighted sum (√T weights: √100=10.0, √50≈7.1, √25=5.0, √10≈3.2, √5≈2.2, √2≈1.4)
weighted = Σ count_QT × √T

# Normalise by years of record
flood_severity_score = weighted / n_years

# Filter threshold used in lp3_filtered_sites mart
WHERE flood_severity_score >= 1.25

Filtering Criteria Summary

1 — HUC 10 Geographic Scope
Applied at extraction time via SiteConfig(huc="10"). Only Missouri River Basin sites are ever ingested. No downstream re-filtering needed.
2 — Minimum Record Length for LP3 Fitting
Sites must have n_years ≥ 10 of annual peak flow data for a statistically meaningful LP3 distribution to be fitted.
3 — LP3 Flood Severity Score ≥ 1.25
Sites are ranked by flood_severity_score (return-period-weighted flood activity rate). Threshold ≥ 1.25 retains sites with meaningful flood signals. Applied in marts.lp3_filtered_sites and in top_30_filtering.ipynb.
4 — Date Cutoff
Data is loaded only up to observation_hour ≤ 2024-08-01 to prevent using partial or provisional data near the present.
5 — Streamflow Quality Cleaning
Negative streamflow values (streamflow_cfs_mean < 0) are set to null — these represent sensor errors or backwater conditions. Null-rate distributions are inspected visually.
